Wenn SubTrack eine Datei nicht lesen kann

Das passiert, bevor das Verschlanken beginnt. SubTrack analysiert jede Datei, die du hinzufügst, und das muss gelingen, bevor es eine Spurliste gibt, über die entschieden werden kann. Scheitert es, steht in der Zeile, dass SubTrack die Videodatei nicht lesen konnte, und die Details darunter nennen den Grund – meist das, was ffprobe zuletzt gemeldet hat.

Woran es meist liegt

  • Es ist gar kein Video. Eine Dateiendung kann alles Mögliche behaupten. Eine Datei ohne Videospur – etwa eine einzelne Audiodatei oder eine Begleitdatei – wird sofort abgelehnt, und das wird auch angezeigt.
  • Sie ist abgeschnitten oder noch nicht vollständig da. Ein laufender Download oder eine Kopie, die noch nicht fertig ist, wirkt wie ein defekter Container, bis das letzte Byte angekommen ist.
  • Der Container wird von diesem Build nicht gelesen. FFmpeg-Builds unterscheiden sich darin, welche Formate sie verarbeiten können.
  • Sie ist verschlüsselt. Gekauftes und geliehenes Video trägt DRM, und SubTrack entfernt es nicht.
  • macOS hält sie zurück. Eine Datei im Container einer anderen App wird sofort abgelehnt, ohne dass eine Rückfrage die Freigabe anbietet.

Was du tun kannst

Wenn macOS den Zugriff verweigert, kopiere die Datei an einen Ort, der dir gehört, und füge die Kopie hinzu. Eine Datei direkt im Container einer anderen App zu lesen, erfordert den Festplattenvollzugriff, den du in den Systemeinstellungen unter Datenschutz & Sicherheit erteilst.

Versuche andernfalls zuerst, die Datei anderswo abzuspielen: Lässt sie sich auch im QuickTime Player nicht öffnen, liegt das Problem an der Datei. Spielt sie dort einwandfrei, öffne Einstellungen ▸ FFmpeg und klicke auf Unterstützte Formate, um zu prüfen, ob dieser Build den Container liest. Wähle dann die Zeile aus und wähle Warteschlange ▸ Auswahl erneut analysieren.
