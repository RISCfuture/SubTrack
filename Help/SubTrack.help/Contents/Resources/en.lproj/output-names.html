Name the files SubTrack writes

SubTrack never modifies a source file — it writes a new one alongside. The naming format decides what that new file is called.

To change it, show the inspector (⌥⌘I), choose Rules, and edit Output name. Each queue has its own.

Build a name from tokens

The format is ordinary text with tokens standing in for each file’s own details:

  • {name} — the source file’s name, without its extension.
  • {n} — the file’s position in the queue.

So {name} (slimmed) turns The Third Man.mkv into The Third Man (slimmed).mkv.

The extension is never part of the format. The output keeps the same container as the source, so SubTrack supplies the extension itself and a format that tried to change it would be describing something it can’t do.

Writing a literal brace

Double a brace to mean it literally: {{name}} produces the text {name} rather than the file’s name. An unrecognized token like {title} is left alone and appears as-is in the name, so a typo produces an odd filename rather than losing anything.

When two names collide

SubTrack refuses to start a queue whose names would destroy a file, and there are exactly two ways that can happen — both with a quick fix. See Fix a naming conflict.
