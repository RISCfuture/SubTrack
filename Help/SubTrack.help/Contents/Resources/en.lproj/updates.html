Check for SubTrack updates

The downloadable version of SubTrack keeps itself current: it asks GitHub whether a newer release exists and offers it to you.

If you don’t see an Updates tab, you’re running the App Store version. It has no update settings at all, because the App Store keeps that copy current — see Choose between the two versions of SubTrack.

Set how often SubTrack checks

  1. Choose SubTrack ▸ Settings (⌘,) and click Updates.
  2. Set Check for updates to Hourly, Daily, Weekly, or Never.
  3. Turn on Include prerelease versions if you want beta builds too.

The schedule only runs while SubTrack is open — there’s no background helper ticking away when the app is quit. A prerelease is a release marked as such on GitHub: a build published for testing before it’s declared final. Leave the switch off and you’re offered finished releases only.

Last checked shows when the last check finished, or a dash if none has. Check Now runs one immediately and tells you either way; it’s dimmed while a check is already running. The same check is available any time from SubTrack ▸ Check for Updates….

Reconsider a version you skipped

When SubTrack offers you an update, one of the buttons in that prompt is Skip This Version. Take it and that release is never mentioned again — not by the scheduled check, and not by Check Now, which will cheerfully tell you you’re up to date. Skipping happens there, not in this pane.

Reset Skipped Versions forgets every version you’ve skipped, so each is offered again. It’s dimmed unless you’ve actually skipped something. If you know a newer version exists and SubTrack insists you’re current, this is the button.

A check is one request to GitHub’s public list of releases. It sends nothing about you, your Mac, or your files — see What SubTrack sends, and what it doesn’t.
