If SubTrack can’t read a file

This happens before any slimming starts. SubTrack inspects every file you add, and that has to succeed before there’s a track list to make decisions about. When it fails, the row says SubTrack couldn’t read the video file, and the detail beneath is whatever ffprobe said on its way out.

What it usually is

  • It isn’t really a video. An extension can say anything. A file with no video track in it — a stray audio file, a sidecar — is refused outright, and says so.
  • It’s truncated, or still arriving. A download in progress or a copy that hasn’t finished reads as a broken container until the last byte lands.
  • The container isn’t one this build reads. FFmpeg builds differ in what they’ve been compiled to handle.
  • It’s encrypted. Purchased and rented video carries DRM, and nothing in SubTrack removes it.

What to do

Try playing the file elsewhere first: if it won’t open in QuickTime Player either, the problem is the file. If it plays fine, open Settings ▸ FFmpeg and click Supported Formats to confirm this build reads that container. Then select the row and choose Queue ▸ Re-scan Selected.
