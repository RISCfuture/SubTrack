Choose where slimmed files are saved

Every queue writes its output somewhere. That somewhere is either a folder you pick, or the folder each source file already lives in.

Set a queue’s destination

  1. Select the queue in the sidebar.
  2. Click Change… in the bar above the queue.
  3. Choose a folder and click Open.

Every file in that queue is written there, whatever folder it came from. This is what you want when you’re collecting the results of a scattered set of sources in one place.

Save next to each source instead

A queue with no destination set saves each slimmed file into the same folder as the file it came from. A season of episodes stays distributed across its per-season folders instead of being flattened into one.

This is the default, and it’s why the destination bar can read Saves next to each source rather than naming a folder.

Saving next to the source is the arrangement most likely to produce a naming conflict, because the output lands in the same folder as the input. If your format produces exactly the source’s name, SubTrack will refuse to start rather than overwrite it. See Fix a naming conflict.

Set the default for new queues

Every new queue starts with a destination of its own, set once in Settings — see Set the default destination for new queues. Changing it never disturbs a queue that already exists.

If SubTrack can’t write to a folder

macOS grants SubTrack access to the folders you choose, and that grant is remembered between launches. If a destination becomes unavailable — an external disk that isn’t mounted, a folder that was moved or deleted — the run stops rather than writing somewhere unexpected.

Choosing the folder again restores access. If the problem is a source file rather than a destination, see If the source file is missing.
