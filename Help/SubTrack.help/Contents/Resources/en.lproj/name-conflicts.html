Fix a naming conflict

SubTrack refuses to start a queue whose names would destroy a file, and there are exactly two ways that can happen.

Two files would be written to the same place

The format doesn’t distinguish between two sources — most often because they have the same name in different folders, like Show.mkv in a Season 1 and a Season 2 folder. Whichever finished last would overwrite the other.

Fix it by making the format produce distinct names. Adding {n} is the quickest way; giving one file its own name in the Override tab is the precise way. Or send the queues to different folders.

A file would overwrite its own source

The format produces exactly the source’s name, and the output folder is the folder the source is in — so SubTrack would be asked to write over the very file it’s reading.

Fix it by adding something to the format, like {name} (slimmed), or by choosing a different output folder. See Choose where slimmed files are saved.

The warning names the files involved, so you can see which ones collided rather than guessing. Start becomes available again the moment no two outputs collide.
