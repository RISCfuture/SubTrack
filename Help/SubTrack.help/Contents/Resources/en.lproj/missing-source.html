If the source file is missing

A queue holds a reference to each file, not a copy of it, and that reference survives quitting SubTrack. So a queue you left overnight can wake up to a file that has been moved, renamed, deleted, or that lives on a disk nobody has mounted yet. The row turns red and reads Source is missing.

There’s a less obvious version of the same thing. Adding a file is what grants SubTrack permission to reach it, and that grant is saved so it still works after a relaunch. Saved grants go stale: the file is exactly where you left it, but the row says the saved reference is no longer valid, or that SubTrack doesn’t have permission to open it.

Restore the file

  1. Put the file back — mount the disk, undo the rename, restore it from the Trash.
  2. Select the row and choose Queue ▸ Re-scan Selected.
  3. If it’s still flagged, choose Queue ▸ Remove Selected (Delete) and add the file again.

Step three is the one that clears a stale permission, and it’s why it’s the standing advice: adding a file is what grants access, so adding it again grants access again. Removing a row never deletes anything from disk.
