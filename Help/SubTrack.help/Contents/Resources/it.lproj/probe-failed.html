Se SubTrack non riesce a leggere un file

Succede prima che inizi qualsiasi alleggerimento. SubTrack analizza ogni file che aggiungi e l’analisi deve riuscire perché ci sia un elenco di tracce su cui prendere decisioni. Se non riesce, la riga indica che SubTrack non ha potuto leggere il file video e il dettaglio sotto ne spiega il motivo, di solito riportando quanto ffprobe ha detto prima di interrompersi.

Le cause più comuni

  • Non è davvero un video. Un’estensione non dice nulla sul contenuto. Un file senza tracce video, come un file audio isolato o un file accessorio, viene rifiutato subito e l’errore lo indica.
  • È incompleto o ancora in arrivo. Un download in corso o una copia non ancora terminata risultano come un contenitore danneggiato finché non arriva l’ultimo byte.
  • Il contenitore non è tra quelli che questa build sa leggere. Le build di FFmpeg differiscono per i formati con cui sono state compilate.
  • È cifrato. I video acquistati o noleggiati sono protetti da DRM e SubTrack non può rimuoverlo.
  • macOS ne blocca l’accesso. Un file all’interno del contenitore di un’altra app viene rifiutato subito, senza alcuna richiesta per consentirne l’accesso.

Cosa fare

Se a rifiutare il file è macOS, copialo in una cartella tua e aggiungi la copia. Per leggere un file direttamente dal contenitore di un’altra app serve l’accesso completo al disco, che si concede in Privacy e sicurezza nelle Impostazioni di Sistema.

Altrimenti, prova prima a riprodurre il file con un altro programma: se non si apre nemmeno in QuickTime Player, il problema è il file. Se invece si riproduce senza problemi, apri Impostazioni ▸ FFmpeg e fai clic su Formati supportati per verificare che questa build legga quel contenitore. Poi seleziona la riga e scegli Coda ▸ Rianalizza selezione.
